## Unreleased

Lineup reads Kimi context from the matching local session, keeps stop and doctor inside their existing limits, and ships dependency licenses with release archives.

- Feature: **Kimi context** reads one regular, nonsymlinked local session whose `state.json` `id` equals the pane's nonempty native session id and whose normalized `cwd` equals the pane cwd. It uses the main agent's last completed `token_counting.turn_recorded.tokens` and the model alias bound before that turn, resolved to `max_input_size` in `config.toml`, or `max_context_size` only when the input size is absent. Duplicate readable matches, an unreadable `state.json` whose session directory is named with that native id, an in-progress turn, a binding after the turn, compaction, a token rebase, a nonpositive window, a non-integer window, and an input size above the context size stay unavailable. A completed turn does not expire by age, including when a timeout restores the previous local reading; a timestamp later than that read's clock is unavailable. Weekly quota stays unavailable, and the reader performs no network I/O. `KIMI_CODE_HOME` defaults to `~/.kimi-code` (empty uses that default); a non-absolute override disables the home. The home itself may be a symlink, and symlinks underneath it are not followed.
- Feature: **Installation** uses `herdr plugin install fujimogn/herdr-lineup` from the public repository. Herdr shows the source and command preview, then runs the manifest build before registration and does not register Lineup if that build fails. There is no `herdr plugin update`; installing again replaces the managed checkout. The Herdr marketplace is an automatic unreviewed index. `--ref` pins a release tag, and installation over an existing local link is refused until that link is removed.
- Fix: **Daemon stop** still waits for the accepted daemon to exit without signaling it and still fails after five seconds if that process is alive. A stalled usage read is not killed, but the wait observes shutdown every 100 ms and returns before the reader timeout, so the following metadata clear still fits in that five-second deadline. Stop still does not join a pending Grok HTTP request.
- Fix: **Doctor** reports `daemon is starting; the first refresh has not completed yet` when no refresh has finished, which is a nonzero exit and is separate from `daemon refresh is unhealthy`. Metadata capacity skips print how many resources the latest refresh skipped and do not by themselves fail doctor; a real refresh failure still exits nonzero. An overlong `control.sock` path is rejected before connect, and the error includes the path's byte length and the platform maximum (the Unix socket limit includes a NUL terminator).
- Fix: **Context** drops the previous local context when directory discovery passes 4,096 entries instead of keeping it the way a read timeout does. Exactly 4,096 entries still succeeds. Without the proven session binding, that pane does not receive the Codex account-quota overlay; Grok's shared weekly value is still applied when network access is enabled.
- Fix: **Grok quota** keeps a weekly percentage that has no reset time visible, without a countdown, until the greater of `usage_max_age_ms` and the query interval plus its timeout and one sidebar refresh interval after the last successful query. That success time is recorded after the response returns. A later transient failure clears a value with no reset; a value with a known future reset is still kept until that reset. `MONTHLY` periods stay unavailable.
- Fix: **Publisher** removes checkpoint rows for resources absent from the authoritative snapshot only after retaining each endpoint's maximum reserved sequence as a floor, so a reused id on that endpoint receives a newer sequence, including across restarts and when the earlier send outcome was ambiguous. Rows and floors for a different socket endpoint are removed once the current endpoint identity is verified. Returning to 0.1.0 after this publisher has written an `endpoint` floor into `sequences.json` fails refresh until that file is removed.
- Fix: **Font setup** can be retried after an install stopped once a terminal write had started, because the ownership record is saved first. Each action lists every changed path. A managed-block or font conflict names the affected path and leaves those bytes unchanged; a symlink at a candidate config refuses the whole action before any font or terminal bytes change. Uninstall removes only recorded, byte-identical blocks and a font file Lineup installed. If it removes nothing managed, it says so and still exits successfully. A missing terminal config keeps its ownership entry. Removing a whole managed block by hand and retrying drops that stale ownership entry; a partly edited block still conflicts.
- Fix: **StatusLine** runs `--then` with `/bin/sh -c`, so `PATH` cannot choose the shell. The chained command still receives the original stdin bytes, and its stdout and exit status are what the command returns.
- Fix: **Daemon logs** record one UTC timestamp and fixed `event` and `reason` categories per line, never error text, paths, credentials, or conversation data. Before a write that would pass 1 MiB, the current log is renamed to a single `daemon.log.1` generation. Repository-heading Git children keep only `PATH`, `HOME`, `TMPDIR`, `XDG_CONFIG_HOME`, and `XDG_CACHE_HOME` from the environment, plus the fixed Git safety settings; they still do not fetch or contact a remote.
- Fix: **Release distribution** adds `THIRD-PARTY-LICENSES.md` to each `herdr-lineup-<tag>-<os>-<arch>.tar.gz` beside the binary, `LICENSE`, `NOTICE.md`, and `README.md`. The release build and CI check that file against the locked binary dependency sources before packaging. The archives are still not standalone plugin installations.
- Fix: **Dependencies** replace the `fs2` file lock with the standard library lock. The session lock remains an advisory lock released when the last shared open-file description closes, and lifecycle commands do not unlock the daemon's inherited descriptor.

## 0.1.0 (2026-10-13)

Lineup brings agent status, session-bound usage, and repository headings to the Herdr sidebar with opt-in setup and reliable background refresh.

- Feature: **Agent rows** show vendor logos and state dots for Claude, Codex, Grok, Antigravity, Kimi, and Hermes, with context usage, weekly remaining quota, and reset countdowns when available.
- Feature: **Local usage** reads Codex and Grok context from the pane's exact native session; Claude and Antigravity provide context and weekly remaining through opt-in statusLine observations, while Kimi and Hermes usage stays unavailable.
- Feature: **Codex context** matches the UI's 12,000-token baseline and keeps the last bound observation through incomplete updates. Large uncompressed rollout files still show context when a recent usage sample is present in their bounded tail.
- Feature: **Row alignment** aligns unavailable context with two-digit percentages under narrow-ambiguous rendering, keeps full `100%` context visible, and pads weekly percentages to at least two digits. Opt-in `non_first_pane_logo_indent` aligns later agent logos beneath repository headings with 0–16 columns of padding.
- Feature: **StatusLine integration** records Claude and Antigravity usage without printing a status line or storing conversation text; `--then` preserves an existing command's input, output, and exit status even when usage capture fails.
- Feature: **Account quota** adds opt-in Codex and Grok weekly queries with `allow_network = true`; refresh continues independently of network requests, and local context still updates with network access disabled. Codex quota requires an exact session verified in the daemon's home; Codex and Grok retain weekly values with known reset times through transient query failures until reset, while authentication failures and explicit Codex account errors clear them; Grok shares its configured account quota across Grok panes and supports weekly periods and environment proxies.
- Feature: **Quota diagnostics** let `doctor` explain the last weekly query result without exposing secrets, including missing, malformed, ambiguous, or unreadable Grok authentication and HTTP failures.
- Feature: **Repository headings** show the repository name and latest local `origin/main` commit time without fetching, at workspace level and on the first pane. Headings follow pane reordering, clear when the repository becomes unavailable, and retain the last value when a read is interrupted in an unchanged workspace; Git queries for one heading share a one-second deadline, disable pagers, filesystem monitors, lazy fetch, and remote protocols, and do not run aliases, hooks, credential helpers, or remote commands.
- Feature: **Background refresh** keeps rows visible through slow reads, renews unchanged rows, and restores missing metadata without letting older updates overwrite newer ones across restarts. Stalled usage reads retain the previous valid observation for the same pane and source, late results are discarded, and required context text takes priority when Herdr's stored-key limit is reached.
- Feature: **Daemon controls** provide `ensure`, `daemon`, `stop`, and read-only `doctor`, with one publisher per Herdr session even during overlapping starts and stops. Startup and workspace focus recover the publisher, controls stay responsive during refresh, settings are bounded, and `doctor` shows the absolute state directory, bounded statusLine record count, and age of the latest record; state lives outside the managed plugin checkout.
- Feature: **Safe shutdown** makes `stop` wait for the accepted daemon to exit without signaling it and fail after five seconds if it is still alive, leaving the Herdr server running. Shutdown ends quota scheduling, cancels Git and Codex query processes, and does not wait for pending Grok HTTP requests.
- Feature: **Compatibility** supports Linux and macOS with Herdr 0.9.3 or later, with bounded socket waits and connections that handle Herdr closing each response.
- Feature: **Sidebar setup** adds explicit `configure` and `unconfigure` actions that serialize edits, back up configuration, preserve unrelated settings, and remove only an unmodified plugin-managed block; startup never edits the user's sidebar.
- Feature: **Icon setup** bundles the HerdrAgentIconsMax icon font with explicit, opt-in install and uninstall commands and `logo_mode` settings; text labels remain available and automatic mode uses them until terminal glyph support is known.
- Feature: **Development and releases** provide Linux and macOS build checks, weekly dependency audits, and version-checked tag releases with dated, previewable notes; missing or empty version notes stop Release creation. Release archives named `herdr-lineup-<tag>-<os>-<arch>.tar.gz` contain the binary, `LICENSE`, `NOTICE.md`, and `README.md`, with SHA-256 checksums; an isolated harness verifies Linux metadata publication without touching the user's Herdr session, authenticated panes need provider credentials, and public plugin installation remains planned.
