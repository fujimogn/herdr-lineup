# Usage sources for six agents

Research snapshot: 2026-10-12. This is an integration feasibility report, not a live account-usage measurement. The crate now implements the readers named in [Lineup readers](#lineup-readers). The matrix below still describes external sources and the retired quota plugin.

## Findings and boundaries

Claude and Agy supply statusLine observations; Codex and Grok have local session observations. Decision 2026-10-12: Kimi and Hermes are **unsupported in v1**. The installed Kimi source live-streams `agent.status.updated` and does not confirm that the event is persisted. Hermes has no confirmed trustworthy persistent context source, and no universal weekly allowance of its own.

## Lineup readers

herdr-lineup reads Codex and Grok context from local session files and leaves their weekly quota unavailable. Codex context is raw occupancy (`total_tokens / model_context_window`) with no baseline deduction, and that reader does not call app-server or open `auth.json`. Grok context comes from the matching session's `signals.json` and does not call the billing API. `herdr-lineup statusline claude` records stdin `session_id`, context, and seven-day remaining; the reader matches that key to the pane's native session and does not read `.claude.json` or account metadata. `herdr-lineup statusline agy` records `HERDR_PANE_ID` as the binding key, plus context and the active weekly pool; it does not copy that pane id into the payload. Both commands keep only those usage fields, the agent, the key, and the observation time under `$HERDR_PLUGIN_STATE_DIR/statusline/`. The statusLine command and the daemon must share that absolute directory. Raw input, transcripts, and credentials are not stored. Kimi and Hermes readers return unavailable. A missing hook, a mismatched identity, or a stale observation still displays `—`.

Context is conversation occupancy, not cumulative tokens billed. Quota belongs to an account and a named window, not to a pane. Display remaining percent as `100 - used_percent`, or `100 * (1 - used_ratio)` for a fraction. Preserve the actual window label: monthly credits are not weekly quota. Missing, expired, unsupported, ambiguous, or failed observations must produce `—`, not zero remaining or a full allowance.

Only source code, official documentation, executable help/version output, and local directory/file names were inspected. No local credentials, environment-secret values, account config contents, conversation payloads, or database rows were read. No authenticated agent-provider API was invoked; `codex app-server`, `hermes usage`, and Kimi usage/status endpoints were **not** executed. `gh api` used the existing GitHub authentication to read repository source; public documentation was retrieved over HTTPS. No agents, servers, or hooks were started or configured.

## Kimi: local installation and conditions

- [K1]: [Official server API](https://www.kimi.com/en/help/kimi-code/cli-server-api). The protocol is experimental; installed OpenAPI/AsyncAPI takes precedence. Status is session-scoped; quota is managed-account-scoped. No endpoint was called during this research.
- [K2]: [Official sessions guide](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/sessions.html). Default layout is `~/.kimi-code/sessions/<workDirKey>/<sessionId>/state.json` and `agents/main/wire.jsonl`; subagents have separate event streams. Files must not be edited. **Confirmed from the guide only:** those paths are the documented session layout. **Not confirmed:** that installed Code 2.1.1 appends `agent.status.updated` to `wire.jsonl`.
- [KL]: Local `kimi --version` reported `2.1.1`; `kimi --help` lists session selection and server modes. Executable resolves to `~/.bun/install/global/node_modules/@moonshot-ai/kimi-code/dist/main.mjs`. Bundle SHA-256: `2563a338c94868a34e1bfd2e5579067d5a472acf4cb0bf350a3bfe1092bbe59d`. **Confirmed in that bundle:** `agent.status.updated` (`AgentStatusUpdated`) is delivered through `withStatusSnapshot` to the SDK `receiveEvent`. **Not confirmed in that bundle:** a write of the same event into `wire.jsonl` or another durable file. Symbols `parseQuotaUsages`, `fetchManagedUsage`, toolkit `getManagedUsage`, and `assembleStatus` name quota and status assembly; they were not executed. The raw managed usage path is the resolved Kimi Code base URL plus `/usages` (default `https://api.kimi.com/coding/v1/usages`), with Bearer OAuth. Region/base-URL overrides exist; do not hardcode a host as account identity.

The following names were observed without opening their contents: `~/.kimi-code/config.toml`, `credentials/kimi-code.json`, `oauth/kimi-code`, `server.token`, `server/instances/`, `session_index.jsonl`, and `sessions/`. Credential layout must be resolved by the installed client; the coexistence of legacy paths does not establish which store is active.

Decision 2026-10-12: Kimi is **unsupported in v1**. The confirmed context observation is a live SDK stream. Persistence of `agent.status.updated` was not confirmed, so a later file read is not a trustworthy context source. Lineup does not subscribe to `receiveEvent`, does not call the local status or quota endpoints, and does not read `server.token`. A local status call in this build can resume a persisted session, so it is not a side-effect-free observer of another running CLI. A future version that confirms a durable, side-effect-free context record needs a new source review. Until then the sidebar shows `—`.

## Hermes: local installation and conditions

- [H1]: [Official CLI reference](https://hermes-agent.nousresearch.com/docs/reference/cli-commands#hermes-usage) documents account usage CLI and JSON output.
- [H2]: [Official session storage](https://hermes-agent.nousresearch.com/docs/developer-guide/session-storage) documents `~/.hermes/state.db` and cumulative token accounting.
- [H3]: [Official sessions guide](https://hermes-agent.nousresearch.com/docs/user-guide/sessions) documents session IDs and compression continuations.
- [HL]: `hermes --version` reported `v0.21.6 (2026.9.24)`, upstream `39faafb6`, installed local HEAD `818c13be1dc4fd28987e1e881a9408224afd4535` with 4,647 carried commits. Installed source is `~/.hermes/hermes-agent/`; `hermes usage --help` confirms `--json` and `--provider`. Source files inspected: `agent/context_breakdown.py`, `agent/account_usage.py`, `agent/account_usage_cache.py`, `hermes_cli/subcommands/usage.py`, `hermes_cli/cli_info_mixin.py`, `hermes_state_usage.py`, and hook payload definitions in `hermes_cli/hooks.py`. These local features are not proof of behavior in an arbitrary upstream release.

Names observed without reading data: `~/.hermes/auth.json`, `.env`, `config.yaml`, `context_length_cache.yaml`, `sessions/`, and `state.db`. Resolve profile-specific `HERMES_HOME` before binding. The DB token counters represent throughput and cannot supply a current-context numerator or a subscription allowance. No current configuration/provider/account was inferred from these files.

Installed `agent/account_usage.py` routes Codex to the configured backend's `/wham/usage` (default `https://chatgpt.com/backend-api/wham/usage`), Anthropic OAuth to `https://api.anthropic.com/api/oauth/usage`, and OpenRouter to its credit reader. The regular CLI fetch can refresh Codex credentials after a 401; the internal `read_only=True` variant avoids that repair, but is not a CLI flag. Provider hooks can perform arbitrary I/O. None of these paths was executed.

For context, a future explicitly configured local telemetry bridge could export only `context_usage_fields` plus native session/pane identity. Request hooks expose session ID, usage, and context length, but reconstructing occupancy from those requires provider-specific cache accounting and must be labelled as last-request usage, not assumed to equal current post-compression occupancy. No such bridge was installed or demonstrated. `/context` is an interactive display, not a stable external JSON endpoint. **Confirmed:** the live helper, the interactive display, and the fact that `state.db` counters are not current occupancy. **Not confirmed:** a trustworthy persistent context source for an uninstrumented pane.

Decision 2026-10-12: Hermes is **unsupported in v1**. Lineup does not treat the live helper, `state.db`, or `hermes usage` as a context or quota reader. The sidebar shows `—`.

## Proposed reader and binding policy

1. Read Herdr's harness, pane ID, native session ID, cwd, and process identity. Preserve agent-native IDs; never identify a conversation by repo/cwd alone. The existing quota plugin uses `pane.session.id()` and process-aware recovery, not a single global latest context.
2. Store context by `(harness, pane lifetime, native session, main agent)` and quota by `(provider, account/profile identity, window)`. Preserve observation time and origin. Clear bindings on session replacement, compression continuation, profile/account change, or pane reuse.
3. For local files, refresh on bounded file changes/statusLine events; retain explicit idle age. For quota, use an opt-in scheduled reader with per-account deduplication/backoff. Do not launch authenticated probes in a default local-only mode. Concrete TTL and cadence remain the OpenSpec's responsibility.
4. Retain only allowlisted numeric fields, window/reset labels, and opaque identity. Do not persist raw statusLine input, auth data, prompts, request traces, server tokens, or full provider errors. Hash/redact account identifiers before display.
5. Validate ranges and scale from the schema, require a positive capacity, and distinguish unsupported from transient failure. Expired/error observations display `—`; an account reset time does not prove that usage is now zero. Never substitute session totals, a different account, or a different conversation.

## Validation and remaining work

Verified by source inspection, then corrected on 2026-10-12: Claude, Agy, Codex, and Grok have named sources, credential boundaries, and binding conditions. herdr-lineup implements those four readers as described under [Lineup readers](#lineup-readers). Live account accuracy was not tested. Kimi is unsupported in v1 because the installed source confirms only a live `receiveEvent` stream. Hermes is unsupported in v1 because no trustworthy persistent context source was confirmed. CLI checks were limited to `--help`/`--version` and `hermes usage --help`. No authenticated accuracy test is claimed.

Remaining checks stay outside this correction: Kimi and Hermes stay unsupported until a persistent context source is confirmed. For the conditional agents, capture redacted synthetic fixtures, prove pane/session/profile joins, and define freshness in OpenSpec. The fallback for an unavailable source is `—`.
